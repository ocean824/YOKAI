# YOKAI — Unreal Production Build

## Foundation
Narrative Pro 2 + Ultra Game Template 1.3. Reconcile subsystem ownership before integration.

## Recommended Fab modules
- Action RPG Template / Flexible Combat System: evaluate; select one as combat base, not both as competing runtime owners.
- Pocket Creature Tamer Adventure: creature capture/roster reference/accelerator; replace rules with YOKAI canonical creature contracts.
- Element Reaction System: elemental interaction accelerator.
- Action RPG Multiplayer Combat: multiplayer reference/adapter if compatible with selected combat authority.
- Boss AI Toolkit + Boss Animations Pack; BlackMoon/Sci-Fi Myth boss assets as reference/content accelerators.
- HKH Attribute System only if superior to chosen foundation; one attribute authority.
- Building/Water/VFX/environment assets only where level requirements call for them.

## Ownership
Narrative Pro 2: quests/dialogue/narrative state. Ultra: generic shell/common systems. YOKAI modules: combat rules, Yokai data/evolution/fusion, Divine Canvas, world state. Specialized assets cannot silently own canonical save/attributes/inventory.

## Implementation
C++ for canonical combat/state/data/network/performance-critical systems; Blueprints for authored encounters, quests, abilities, UI wiring and content where appropriate. Data Assets/Data Tables for creatures/items/abilities. GAS may be evaluated, not assumed.

## Ludus AI
Use as Unreal development assistant where its installed/current capabilities support Blueprint/C++/editor workflows; generated changes remain subject to XYRA review and source control.

## Release gates
60 FPS target profile defined per platform; deterministic save migrations; boss/combat frame-time budgets; multiplayer authority/desync tests; creature/content validation; packaged-build Gauntlet.
